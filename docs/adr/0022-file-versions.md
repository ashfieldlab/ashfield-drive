# ADR-0022: 파일 버전: 10분 묶기 + 한도 포함하되 저장은 막지 않음

- **상태**: 결정 (2026-10-09)
- **컨텍스트 ADR**: [0005](0005-storage-s3-compatible-presigned.md) presigned 저장, [0015](0015-desktop-client.md) 데스크톱 싱크(덮어쓰기의 유일한 경로), [0016](0016-e2e-encrypted-vault.md) 보안 폴더

덮어쓰기가 옛 내용을 즉시 지워서, 싱크가 잘못 덮으면 복구할 길이 없었다. 덮어쓰기와 복원 때 옛 내용을 **파일 버전**으로 남긴다. 그런데 덮어쓰기를 만드는 쪽은 데스크톱 싱크뿐이고, 싱크는 오피스 자동 저장까지 그대로 올려 보낸다. 그래서 단순한 "최근 N개" 보존이나 "한도 초과 시 거절" 규칙은 둘 다 사용자를 놀라게 한다. 그래서 아래처럼 정했다.

## 결정

1. **묶기**: 같은 사람이 10분 안에 다시 저장하면 새 버전을 만들지 않는다. 복원은 예외로, 항상 버전을 남긴다. 기준을 "누구든"이 아니라 "같은 사람"으로 둔 이유는, 공유 폴더에서 다른 사람이 덮어쓴 직전 상태를 지키기 위해서다.
2. **보존**: 버전마다 30일이 지나면 삭제한다(휴지통 보존 기간과 같다). 파일당 상한은 50개다. 버전 고정(영구 보관)은 만들지 않는다.
3. **한도**: 버전도 워크스페이스 한도와 소유자 개인 한도에 포함한다. 다만 한도가 차면 저장을 막지 않고 버전을 자동으로 지운다. 지우는 순서는 그 파일의 옛 버전 → 같은 소유자의 다른 파일 → 워크스페이스 전체다. 저장을 거절하는 건 현재 파일들만으로 한도를 넘을 때뿐이다. 자동 삭제는 감사로그에 남긴다.
4. **권한**: 버전 열람·다운로드·복원은 쓰기 권한 이상, 버전 삭제는 관리 권한만 가능하다. 읽기 공유와 외부 링크로는 현재 내용만 보인다(지운 내용이 공유받은 사람에게 새지 않게).
5. **삭제 연동**: 휴지통에 있는 동안 버전도 같이 보관한다. 영구 삭제되면 함께 지운다. 보안 폴더 파일은 즉시 함께 지운다.

## 버린 대안

- **최근 N개만 보존**: 가장 단순하지만, 자동 저장이 몰리면 어제의 정상 버전이 몇 시간 만에 밀려난다.
- **Nextcloud식 시간 솎아내기**(최근은 촘촘히, 오래된 것은 듬성듬성): 정확하지만 규칙이 복잡하다. 묶기 + 30일로 대부분 해결된다. 필요해지면 데이터 모델은 그대로 두고 정리 규칙만 바꾸면 된다.
- **한도 미포함**: 원가가 숨겨져 외부 판매 가격 계산이 틀어진다.
- **한도 초과 시 저장 거절**: 사용자는 "버전 때문에 저장이 안 된다"는 이유를 이해할 수 없다. 싱크에서는 조용한 실패가 된다.
