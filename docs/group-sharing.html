그룹 공유: 설계 (디렉터리 부서 기반)

현재 비활성 (2026-10, ADR-0023). 외부 디렉터리 연동을 제거해 부서 소스가 없다. 그룹 공유·부서 폴더 생성은 400, 부서 목록·접근집합은 비어 있다 (backend/app/services/departments.py). 기존 그룹 share 는 권한을 주지 않고, 기존 부서 폴더는 생성자·System Admin 만 접근한다. 아래는 원래 설계 기록이다.

일반 공유 폴더를 디렉터리 조직도의 부서에 공유해, 그 부서 + 하위 산하 전원이 자동 접근. workspace는 부서를 만들지 않고 실제 조직도를 그대로 쓴다.

확정: 인증(B 리소스서버) 검증 완료 (2026-06-23) · 구현 전
인증 검증됨: workspace가 유저의 Keycloak 토큰을 Authorization: Bearer로 외부 디렉터리에 포워딩 → 외부 디렉터리 validate_bearer_token이 검증 → directory_api가 그 유저 회사 스코프로 응답. 게이트웨이·서비스키 불필요. 개발 환경에서 list_departments 200 + 실제 부서트리 확인. (응답의 sid=Guest 쿠키는 stateless 토큰 인증의 정상 동작: 본문 데이터가 인증 증거)

3인증 (workspace→외부 디렉터리)B · 리소스 서버: 유저 토큰 포워딩oauth2-proxy 방향(엣지 인증 + 백엔드 리소스서버)과 일치. 서비스키·임퍼소네이션 없음. 검증 완료.
4멤버십 판정어댑터 + 캐시 (웹훅 무효화는 나중)directory_api 조회를 회사별 캐시. 멤버십 변경 반영 지연은 추후 외부 디렉터리 웹훅으로 invalidate.

workspace 쪽: 새로 만들 것

1외부 디렉터리 어댑터 (토큰 포워딩 + 캐시)

ExternalDirectoryClient:
  base = DIRECTORY_URL                       # 직접 (게이트웨이 우회 OK: B 검증됨)
  call(method, user_access_token):
     GET {base}/api/method/{method}
     Authorization: Bearer {user_access_token}
  list_departments(token)         → 캐시(회사별)
  members_of(dept_id, token)      → search_colleagues 기반, 캐시
* user_access_token: NextAuth 세션의 access_token 을 backend 호출에 전달.
* 캐시 무효화: 초기엔 TTL, 추후 외부 디렉터리 웹훅.

2저장: FileShare 확장

FileShare:
  node_id
  grantee_sub       str | null    # 개인 공유 (기존)
  grantee_group_id  str | null    # ★신규: directory department_id 참조 (문자열)
  role              read | write | manage
  (grantee_sub / grantee_group_id 중 정확히 하나)

그룹 멤버 복제 안 함: 외부 디렉터리 department_id만 참조. 멤버십은 판정 시 어댑터로 해석.

3권한 해석: effective_permission 확장

요청 유저 U 의 부서 = 어댑터로 해석 (U 토큰)
노드에 걸린 group-share(dept D) 마다:
   U 의 부서가 subtree(D) 안인가? (parent 체인/lft 재구성)
   → 맞으면 그 share 의 role
유효 권한 = max(개인 share, 그룹 share …), 조상 폴더 walk (기존과 동일). deny 없음.

4공유 UI

공유 모달에 "그룹(부서)" 선택기: list_departments 트리에서 선택 + role. 기존 개인 공유와 동일 UX.

인증 흐름 (B)

[브라우저] →(쿠키)→ [workspace BFF/백엔드]
                         │  Authorization: Bearer {user access_token}
                         ▼
                      [외부 디렉터리] validate_bearer_token → set_user(email)
                         │  directory_api (그 유저 회사 스코프)
                         ▼
                      부서/멤버 응답
※ 미래 oauth2-proxy 전환 시: 엣지에서 인증 + 토큰 패스스루 → 외부 디렉터리는 그대로 리소스서버.

남은 작은 결정 / 리스크

  • access_token 노출: NextAuth 세션의 access_token 을 backend 의 외부 디렉터리 호출에 전달하는 경로 확보(서버 측).
  • 캐시 무효화: 초기 TTL → 추후 외부 디렉터리 웹훅(부서/직원 변경 시).
  • DIRECTORY_URL: workspace backend → 외부 디렉터리 직접 도달 주소(클러스터 내부 서비스 or 공개).
  • 회사 경계: 활성 회사 부서만 노출·해석. 멀티테넌트 격리 유지.
  • 토큰 만료: 1시간 수명. backend 호출 시 유효 토큰 확보(갱신 흐름).

4단계: 팀 폴더 (Team folders, 옵션 B 확정)

표현 = shared scope + 팀폴더 바인딩 + ACL 오버라이드 (vault 패턴 그대로). "회사 전원 write"를 끄고 부서 ACL 로 대체. 주인 없음 → orphan 없음. 회사 공용 자산.

데이터

team_folders                      # vaults 테이블과 평행
  node_id        PK, FK nodes      # 팀폴더 루트 (shared scope)
  company_id     FK companies
  department_id  str               # 디렉터리 부서 (이 폴더가 누구 것인지)
  created_by
  created_at

접근: effective_permission (shared 분기에 추가)

shared 노드의 조상 중 team_folders 가 있으면 (vault 처럼 재귀 CTE):
   회사 전원 write 대신 →
   부서 ∈ 유저 접근집합(access_department_ids, 3단계 캐시) ? write : 0
   (creator/회사 admin → manage)
* 즉 팀폴더 = "그 부서(+하위)만 접근하는 shared 서브트리". vault 의 부서판.

API

POST   /api/v1/team-folders   {department_id, name}   # 회사 admin 전용
         → shared 폴더 노드 + team_folders 행 생성
GET    /api/v1/team-folders                            # 내가 멤버인 팀폴더 목록
         (유저 접근집합 ∋ 바인딩 부서)
DELETE /api/v1/team-folders/{node_id}                  # admin (폴더+바인딩 제거)

목록 분리

팀폴더 루트는 좌측 "Team folders" 섹션에만 노출. 일반 "회사 공유"(shared 루트) 목록에선 제외(team_folders 에 있는 node 빼기): 중복/혼선 방지. (sync 의 vault 제외와 동일 결)

모델 A 와의 공존

3단계의 FileShare.grantee_group_id = "내 개인 폴더를 팀에 임시 공유"(ad-hoc). 팀 폴더(B) = 상설 부서 공용 공간(바인딩 기반). 둘은 다른 UX 라 공존.

엣지 / 나중

  • 디렉터리 부서 삭제 → 팀폴더 orphan(멤버 해석 불가) → 추후 처리(고아 표시/재바인딩).
  • 부서마다 팀폴더 자동 생성 → 나중 (지금은 admin 수동 1회).
  • creator 이탈해도 무관(주인 없는 shared 자산).
